# Take-home exercise: repository evaluation

## The problem

Your team is about to take on a new open-source dependency. Someone has to decide whether that's a good idea — not “does it work today”, but “will we regret this in two years.”

Today that decision gets made by opening the GitHub page, scrolling for a bit, and going with a gut feel.

**Build something better. GitHub's public API is your data source.**

## Stack

React with TypeScript on the frontend, Python with Django on the backend. Beyond that, your choices.

## Scope

Time-box it. We're not looking for a weekend's work — something small enough to have been a single evening is the right shape. Decide what matters, build that, and note down what you'd do next.

One thing done well beats four things half-built.

No auth or database needed unless you want one. The unauthenticated GitHub API is rate limited to 60 requests an hour — that's expected, and dealing with it is part of the problem.

## In your README

- What does “will we regret this” mean, and how did you decide?
- What did you deliberately cut?
- How did you use AI tools? Use them — we do. We just want to know what's yours.
